# 轻跑计划 · Running, gently

> 给身体留一点空间，也给坚持一点温柔。  
> 项目署名：**GPT小熊**

一个轻量、响应式的跑步计划网页。它不催促你追赶速度，而是帮助你安排跑步、认真休息，并在愿意的时候记录当下的路线。

**在线体验：** https://euneirobyte.github.io/Healthy-_-Running_Plan/  
**源代码：** https://github.com/EuneiroByte/Healthy-_-Running_Plan

## 设计原则

- **安静、柔软、清楚。** 以柔和中性色、细边界、适度留白和克制动效建立界面层次。
- **先照顾人，再记录数字。** 不鼓励硬撑；休息、补水和身体反馈同样重要。
- **由用户决定。** 定位不会自动开启，只有点击相关按钮后才会请求浏览器权限。
- **尽量少收集。** 跑步打卡保存在当前浏览器；实时轨迹只在当前页面内存中显示，不上传、不持久化。

## 功能

### 跑步计划
- 计划周期：2026 年 10 月 15 日至 2027 年 1 月 1 日。
- 38 个计划跑步日，每个跑步日安排两次，共 76 次打卡。
- 41 个完整休息日，保留恢复空间。
- 月历导航、当天安排、独立打卡、完成统计与目标进度。
- 浅色 / 深色主题、响应式布局、键盘焦点样式和减少动态效果支持。

### 实时定位与路线
- 点击「获取定位」后，浏览器才会请求地理位置权限。
- 点击「开始记录」后，页面通过浏览器 Geolocation API 持续读取位置，并在地图上绘制本次轨迹。
- 显示本次距离与记录时长，并提供轻柔、非竞争性的鼓励提示。
- 点击「结束记录」即可停止位置监听。

当前地图采用 **Leaflet + OpenStreetMap**，不需要在公开仓库中写入地图 AK，也不需要单独搭建地图代理服务器。地图组件和底图需要网络连接才能加载。

## 地图方案评估

本项目目前部署在 GitHub Pages，是纯静态网站：

- **百度地图：** 浏览器端 AK 会出现在前端请求中。可以配置 Referer 白名单降低滥用风险，但百度官方也提供通过服务端代理隐藏 AK 的方案。若要把密钥妥善留在服务端，需要额外的代理服务，单靠 GitHub Pages 无法运行该代理。
- **Google Maps：** 需要 API Key，并要求为相关项目启用计费；前端密钥还应限制可访问的网站来源和可调用的 API。
- **当前选择：** 先使用 Leaflet + OpenStreetMap 完成免密钥的定位、轨迹和距离记录。这样更适合当前的静态部署方式，也避免把个人 AK 直接写入公开代码。后续如果需要切换百度地图，可以先确定代理服务与预算，再接入地图提供商。

参考文档：
- [百度地图 JSAPI 4.0：使用代理保护 AK](https://lbs.baidu.com/docs/jsapi?title=jsapi4/concepts/proxy)
- [Google Maps Platform：获取与限制 API Key](https://developers.google.com/maps/documentation/javascript/get-api-key)
- [Leaflet 文档](https://leafletjs.com/reference.html)
- [OpenStreetMap 版权与署名](https://www.openstreetmap.org/copyright)

## 隐私与使用说明

- **跑步打卡：** 使用浏览器 localStorage 保存于当前设备，不会上传到本项目服务器。清除浏览器站点数据会同时清除打卡记录。
- **实时位置：** 只有在你主动点击定位或开始记录时才会请求权限。轨迹、坐标和距离仅保留在当前页面运行期间，刷新或关闭页面后即清空。
- **地图网络请求：** 地图需要向 Leaflet CDN 与 OpenStreetMap 瓦片服务请求资源。地图提供商可能会接收到加载地图所必需的网络请求信息。
- **定位条件：** 浏览器通常要求在 HTTPS 或本地安全环境下使用定位。GitHub Pages 使用 HTTPS；定位精度仍受设备、信号、系统设置和浏览器后台策略影响。
- **记录限制：** 这是轻量网页记录工具，不是专业运动手表。距离由定位点估算，GPS 漂移可能造成误差；手机锁屏或浏览器进入后台时，系统也可能降低定位频率或暂停页面执行。
- **运动安全：** 以轻松、可持续为原则。若出现持续疼痛、头晕或明显不适，请停止运动并优先恢复。

## 本地运行

本项目是原生 HTML、CSS 与 JavaScript，无需安装构建工具。可直接用浏览器打开 index.html；如需测试定位，建议通过本地 HTTPS 或开发服务器访问。

## GitHub Pages 部署

1. 打开仓库的 **Settings → Pages**。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
3. 推送到 main 分支后，工作流会自动发布网站。
4. 在 [Actions 页面](https://github.com/EuneiroByte/Healthy-_-Running_Plan/actions) 查看构建与部署结果。
